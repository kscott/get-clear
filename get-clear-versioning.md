# Get Clear — Versioning

## Strategy

Each tool has its own independent version (`builtVersion`) that advances on its own schedule. The suite version (`suiteVersion`) represents the PKG release — it's the same across all tools and advances when a PKG is cut.

Both constants are baked into `Version.swift` at build time by `scripts/bump-version`. The version string shown to users is:

```
reminders 1.2.1 (Get Clear 1.3.0)
```

This answers two questions at once:
- "Is my reminders tool current?" — the tool version
- "What PKG release is this from?" — the suite version

The UpdateChecker uses `builtVersion` only, since it checks the tool's own release page.

---

## Semver levels

### Tool version (`builtVersion`)

| Change | Level |
|---|---|
| New command or subcommand | minor |
| New keyword or argument to existing command | minor |
| Bug fix, error message improvement | patch |
| Breaking change to argument order or output format | major |

### Suite version (`suiteVersion`)

| Change | Level |
|---|---|
| PKG release with one or more tool updates | minor |
| Major overhaul, incompatible change | major |
| Hot-fix PKG release (single tool patch) | patch |

---

## What goes in `Version.swift`

Generated by `scripts/bump-version`. Never edit manually.

```swift
// Generated — do not edit manually. Use scripts/bump-version in get-clear.
let builtVersion = "1.2.1"   // this tool's own version
let suiteVersion = "1.3.0"   // PKG release version
```

The `get-clear` umbrella uses the same pattern:

```swift
let builtVersion = "1.3.0"   // same as suiteVersion — umbrella tracks the suite
let suiteVersion = "1.3.0"
```

---

## `bump-version` workflow

### Bump suite version and specific tools

```
./scripts/bump-version <suite-version> [tool:version ...]
```

Examples:

```bash
# Bump suite to 1.4.0, bump reminders to 1.4.0 — other tools stay at their current version
./scripts/bump-version 1.4.0 reminders:1.4.0

# Bump suite to 1.4.0, bump two tools
./scripts/bump-version 1.4.0 reminders:1.4.0 calendar:1.3.1

# Bump suite only — no tool builtVersions change
./scripts/bump-version 1.4.0
```

For every tool:
- `suiteVersion` is always updated to `<suite-version>`
- `builtVersion` is updated only if that tool appears in `[tool:version ...]`

### What happens

1. Update get-clear `VERSION` and `Version.swift` (both constants)
2. Commit + push get-clear
3. For each tool repo: update `Version.swift` with new `suiteVersion` (and `builtVersion` if specified), commit, push
4. Poll GitHub releases for each tool until the fresh binary appears (by `updatedAt > push timestamp`)
5. Trigger PKG build via `gh workflow run release.yml`

---

## Rules

- **Never manually edit `Version.swift`** in any repo. Always go through `bump-version`.
- **The umbrella `builtVersion` always matches `suiteVersion`.** The `get-clear` binary is the PKG itself — it has no independent version.
- **Patch releases for a single tool** get a suite minor bump (or patch if truly isolated). Err toward bumping the suite patch.
- **The PKG is the unit of distribution.** Users install and update the PKG. Individual tool versions exist so power users can identify exactly what they have, but the PKG version is the support surface.

---

## First public release

Suite version `1.0.0` ships when the going-live checklist is complete (see `going-live.md`). All tool `builtVersion` values will be set to `1.0.x` (preserving patch history accumulated during development) and `suiteVersion` will be `1.0.0`.
